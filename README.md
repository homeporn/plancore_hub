# PlanCore

Инструмент **аудита и построения календарно-сетевых графиков (КСГ)** на чистой
архитектуре: доменное ядро без зависимостей, тонкие слои данных и UI.

Загрузите график из Excel — система проверит логику, структуру СДР, связи и
даты; либо соберите график с нуля мастером, в редакторе или из шаблона,
рассчитайте критический путь и посмотрите логическую сеть.

## Структура (монорепо, pnpm + Turborepo)

```
apps/
  web/                # Next.js 15 (App Router) — UI, бизнес-логики не содержит
packages/
  core/               # @plancore/core — чистый TS-домен (без React и сети)
    src/schedule/     # каноническая модель ScheduleRow, типы связей, helpers
    src/audit/        # движок аудита + playbook рекомендаций
    src/cpm/          # метод критического пути (ES/EF/LS/LF/резервы)
    src/calendar/     # рабочий календарь и ограничения дат
    src/import/       # парсер Excel (TaskRow DTO) + единый маппер в ScheduleRow
    src/graph/        # построение/раскладка/диагностика логической сети
    src/scaffold/     # генерация графика из шаблонов (wbs_templates и пр.)
    src/autofix/      # детерминированная автокоррекция находок аудита
    src/library/      # типы справочников + workflow-автомат библиотеки
  data/               # @plancore/data — Supabase-репозитории и мапперы БД ↔ домен
  store/              # @plancore/store — кэширующий фасад Library/справочников
supabase/
  migrations/         # схема БД в SQL (источник истины)
  functions/library/  # Edge Function — оркестратор записи библиотеки
```

### Архитектурные принципы
- `core` ни от чего не зависит и покрыт тестами.
- `data` зависит от `core`, маппит БД ↔ домен.
- `store` — единый шлюз чтения справочников/библиотеки (+ запись через оркестратор).
- `web` зависит от `core`/`data`/`store`, **бизнес-логику не содержит**.
- Единая модель `ScheduleRow`; `TaskRow` — только DTO импорта Excel.
- TypeScript `strict` (включая `strictNullChecks`) с самого начала.

## Возможности и маршруты

| Маршрут | Назначение |
|---------|-----------|
| `/hub` | Главный экран: все проекты пользователя со сроками и статусом; создание проекта, выбор текущего |
| `/wizard` | Мастер создания графика по шагам (тип объекта → параметры → предпросмотр) |
| `/editor` | Табличный редактор графика с живым расчётом CPM |
| `/app` | Импорт Excel → аудит качества + автокоррекция находок |
| `/graph` | Логический сетевой граф с диагностикой (циклы, висячие связи) |
| `/library` | Справочники (разделы РД/ПД, организации) и методологии с версиями и workflow |

Сквозной «текущий проект» (`ProjectProvider`) связывает режимы между собой.

## Команды

```sh
pnpm install
pnpm typecheck    # tsc по всем пакетам
pnpm test         # vitest
pnpm build        # сборка пакетов и приложения
pnpm dev          # запуск apps/web
```

## Backend (Supabase)

Схема БД хранится в `supabase/migrations` как источник истины и проверяется в
CI применением на чистый Postgres. Подробности и рабочий процесс миграций —
в [`supabase/README.md`](supabase/README.md); оркестратор библиотеки —
в [`supabase/functions/library/README.md`](supabase/functions/library/README.md).

`apps/web/.env.local` (не коммитится):
```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=...
```

Типы БД сгенерированы из схемы (`packages/data/src/supabase/database.types.ts`);
CI предупреждает о расхождении с миграциями.

## Статус

Базовый MVP (Волны 0–3): каркас монорепо, доменное ядро, импорт+аудит,
авторизация и сохранённые проекты.

| Волна | Содержание | Статус |
|-------|-----------|--------|
| 4 | Редактор графика + рабочий календарь + ограничения дат CPM | ✅ |
| 5 | Логический сетевой граф | ✅ |
| A | Создание графика из шаблонов (scaffold + мастер) | ✅ |
| B | Hub проектов + сквозной контекст проекта | ✅ |
| C | Автокоррекция аудита, Store, UI библиотеки, оркестратор записи | ✅ |
| D | Захват схемы БД в миграции + CI | ✅ |

### Бэклог
- **Волна UI** — компонентная база `packages/ui` (shadcn / Mantine / Tailwind-primitives).
- **Волна E** — двунаправленный Canvas (холст ↔ график).
- Кнопка «Из шаблона» прямо в редакторе.
- Деплой Edge Function `library` на боевой проект.
